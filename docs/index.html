Can a fresh coding agent get itself a working inbox?

I gave 8 fresh Claude Code runs a goal that needed email and never named a product. Each started in an empty folder with no memory, no MCP servers, and no project context. The runs that chose AgentMail were then allowed to sign up with no human email attached. Run on 2026-11-19 with Claude Code 2.1.328, for about $6.90 in total.

6 of 8 runs chose AgentMail and signed up. None could prove the inbox receives mail.

Why it stopped

Sign-up was the easy part: HTTP 200 on the first try in every run, in 2 to 5 tool calls. Testing the inbox was the hard part.

A sign-up with no human attached is receive-only by design, so it cannot send even to itself, and outbound port 25 was blocked, so every run ended with 0 messages and asked a person to send a test email. When one was sent, it arrived.

Where the agents got stuck

1. No way to test receipt without a human (6 of 6)

3 runs tried a self-send and got 403 message_rejected ("not in allow list"), and 5 tried direct SMTP to the MX and timed out on port 25.

"I'm blocked because there is no way to get an email into it without a human email address or a second account." (G2)

2. The free tier is stated two ways

llms.txt says 3,000 emails a month; the quickstart and the sign-up limits page say 100 a day. G3 flagged this as a conflict. A sign-up with no human attached gets daily_send_limit: 0, which matches the limits page ("nobody, if no human is attached") but is not mentioned in llms.txt or the quickstart.

3. The rejection message leads with allow lists

The fix text suggests adding recipients to the send allow list first and mentions the unverified-account rule only at the end. Two runs had to check the docs to find the real cause.

What worked well

Discovery is strong. On generic queries, agentmail.to or docs.agentmail.to showed up in the first search results every time, one run (G7) named AgentMail in its first query, and runs read the agent-readable .md docs and llms.txt directly. Three runs noticed that many comparison pages were AgentMail's own posts and leaned on the API docs instead.

Limits

One model in one harness, one run per goal, on one network with port 25 blocked. It shows where a careful agent stops, not how often every agent would. Six receive-only test inboxes were created (pranav-coldstart-01 to 06) and the agents sent no email to anyone.
